# Sarah Miller — 200 Delicious Recipes (landing page, STAGING build)

Static, mobile-first sales landing page (plain HTML/CSS/JS). **Not approved for publication.** No checkout, payment, or add-on logic lives here; purchase buttons point to one configurable Whop URL.

## Run locally
```bash
npm install          # only needed to (re)generate images (sharp)
npm start            # serves on http://localhost:4173
```
`npm start` runs `server.mjs`: it serves the `public/` folder (exactly what Netlify publishes): static files with clean URLs (`/privacy-policy`, `/refund-policy`, `/contact`) plus the `/api/contact` handler. Pages use root-absolute links, so open them through a server (not by double-clicking the file).

## Configure (`public/js/site-config.js` — single source)
| Key | Purpose |
|---|---|
| `WHOP_CHECKOUT_URL` | `https://…whop.com/…` URL. Empty → all purchase buttons disabled with "Checkout link pending setup". Non-https or non-allowed hosts are rejected. |
| `SITE_URL` | Enables canonical + `og:url` once the domain is known. |
| `CONTACT_EMAIL` | Support email (`millersarahj980@gmail.com`). |
| `CONTACT_ENDPOINT` | Contact form endpoint, default `/api/contact`. |
| `LEGAL_EFFECTIVE_DATE` | Effective date shown on the Privacy and Refund pages. Empty = "To be announced". Set it only after legal approval. |
| `BRAND_NAME` | Footer copyright name (approved business/brand name). |
| `STAGING` | `false` hides QA notices. |

## QA mode
QA notices are hidden from the normal view. Open `http://localhost:4173/?qa=1` to see the preview-verification warning and "Checkout link pending setup" (only while `STAGING` is `true`). The browser console also lists the launch blockers. Purchase buttons stay disabled with an empty `WHOP_CHECKOUT_URL`, and the note stays in the DOM (visually hidden) for screen readers.

## Institutional pages and footer
- `public/privacy-policy.html`, `public/refund-policy.html`, `public/contact.html` are generated by `npm run build:pages` (`scripts/build-pages.mjs`). The same script injects the **one shared footer** into those pages and into `public/index.html`. The generated files are committed, so Netlify needs no build step. Edit the copy or footer in the script, then run it again.
- There is intentionally no Terms of Service page or link.
- Internal legal notes: `LEGAL_REVIEW_CHECKLIST.md` (never publish; it is listed in `.gitignore` and kept locally only).

## Contact form
The form posts JSON to `/api/contact`. On Netlify that path is served by `netlify/functions/contact.mjs`, a thin adapter around `api/contact.js` (dependency-free handler, also used by `server.mjs` locally). It validates and normalizes input, strips control characters (header injection), limits payload size, checks the Origin, rate-limits per IP (in memory, per instance), uses a hidden honeypot field, escapes HTML in the email, and never logs personal data. It reports success only after the email provider accepted the message.

To make it deliver you must configure the host (nothing secret belongs in this repo or the browser):
| Variable | Purpose |
|---|---|
| `RESEND_API_KEY` | API key from https://resend.com (or adapt `api/contact.js` to your provider) |
| `CONTACT_FROM` | Verified sender, e.g. `Sarah Miller Website <support@your-domain.com>` |
| `CONTACT_TO` | Optional; defaults to `millersarahj980@gmail.com` |
| `ALLOWED_ORIGIN` | Optional; your site origin, if the form is served from another host |

Set them in Netlify (Site configuration → Environment variables). Without them the endpoint answers 503 and the form shows the error message ("We couldn't send your message…").

## Images
- `assets/original/` (26 PNGs, unmodified) and `assets/optimized/` (all generated variants) stay **local only** and are git-ignored.
- `public/assets/optimized/` holds the 68 files the pages actually reference (WebP 480/768/1024/full width + JPEG/PNG fallbacks) and is what gets committed and published.
- Regenerate with `npm run optimize` (writes to `assets/optimized/`), then copy the files you need into `public/assets/optimized/`. Variants not referenced by the pages (`hero-portrait*`, `hero-square*` except `hero-square-1024.webp`) are intentionally not published.

## Deploy (Netlify)
Configured in `netlify.toml`: publish directory `public`, functions directory `netlify/functions`, **no build command**, Node 20. Cache headers are defined there too (HTML and `site-config.js` always revalidate; CSS/JS 1 hour; images 1 day + stale-while-revalidate). File names are not fingerprinted, so nothing is marked `immutable`.

## Going live (after every blocker in QA-CHECKLIST.md is closed)
1. Set `WHOP_CHECKOUT_URL`, `SITE_URL`, `BRAND_NAME`; set `STAGING: false`.
2. Remove `<meta name="robots" content="noindex, nofollow">` from `index.html` and remove it from `privacy-policy.html`, `refund-policy.html` and `contact.html` too (edit `scripts/build-pages.mjs`, then `npm run build:pages`), after legal approval and with `LEGAL_EFFECTIVE_DATE` set.
3. Add `og:image` with an absolute URL.
